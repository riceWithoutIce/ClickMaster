# 版本记录

本目录只保存小型文本元数据，不保存 EXE、安装包、压缩包或源码快照。

| 文件 | 职责 |
| --- | --- |
| [VERSION](VERSION) | 人工维护的版本号唯一来源 |
| [CHANGELOG.md](CHANGELOG.md) | 面向使用者的版本变化，未发布内容放在 Unreleased |
| [releases.json](releases.json) | 发布索引、来源快照、产物摘要、校验值与保留状态 |

## 版本号

采用 SemVer：`主版本.次版本.修订版本`，预发布可用 `-alpha.1`、`-beta.1`、`-rc.1`。当前 `0.1.0-dev.0` 仅是此前暂存的开发标识，首个正式开发版本仍待确认，不表示已有可运行构建或发布。

未来脚本从 VERSION 同步 package.json、Cargo.toml 和 Tauri 配置，并在构建前核对一致性。具体 Windows 安装器版本映射在选定打包方式后实现，不能假设预发布字符串可原样用于所有安装器字段。

版本号一经对外发布不得用于另一份不同内容的安装包。修复应递增版本号；相同版本的重构建只允许停留在构建暂存，并不得覆盖已发布产物。

## 发布索引

`releases.json` 初始为空索引。实际发布才新增条目，至少记录：

- 版本、发布渠道（stable/preview）、日期、架构及分发格式。
- 可归属的源码提交；尚无 Git 时不得伪造提交号或宣称可按标签恢复。
- 产物文件名、字节数、SHA-256、运行时前提与发布时的验证结论/证据位置。
- 本地保留状态：current / archived / preview / removed，以及当前相对路径或移除时间。

历史元数据长期保留；二进制淘汰后更新为 removed，不删除该版本的变更和校验信息。哈希与提交记录只能追溯，不能恢复已删除的原始安装包，也不保证重建字节一致。

依赖锁文件留在源码工程并纳入后续 Git 版本控制，不复制到每个历史版本文件夹。
