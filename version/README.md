# 版本记录

本目录只保存小型文本元数据，不保存 EXE、安装包、压缩包或源码快照。

| 文件 | 职责 |
| --- | --- |
| [VERSION](VERSION) | 人工维护的版本号唯一来源 |
| [CHANGELOG.md](CHANGELOG.md) | 面向使用者的版本变化，未发布内容放在 Unreleased |
| [releases.json](releases.json) | 发布索引、来源快照、产物摘要、校验值与保留状态 |

## 版本号

采用SemVer，当前 `0.1.0` 为首个正式版。`VERSION` 为唯一人工编辑版本源；`node scripts/version.mjs --sync` 同步package、Cargo、锁文件自有包和Tauri字段，`--check`验证，不升级依赖。

Tauri构建将完整SemVer写入PE FileVersion/ProductVersion字符串，数值版本采用Tauri自有转换规则，候选包须核对实际资源；数值字段不能独立表达rc身份。未发布索引保持空，候选来源清单位于任务暂存目录。

版本号一经对外发布不得用于另一份不同内容的发布包。修复应递增版本号；相同版本的重构建只允许停留在构建暂存，并不得覆盖已发布产物。

## 发布索引

`releases.json` 在正式包验收并发布时新增条目，至少记录：

- 版本、发布渠道（stable/preview）、日期、架构及分发格式。
- 可归属的源码提交；尚无 Git 时不得伪造提交号或宣称可按标签恢复。
- 产物文件名、字节数、SHA-256、运行时前提与发布时的验证结论/证据位置。
- 本地保留状态：current / archived / preview / removed，以及当前相对路径或移除时间。

历史元数据长期保留；二进制淘汰后更新为 removed，不删除该版本的变更和校验信息。哈希与提交记录只能追溯，不能恢复已删除的原始安装包，也不保证重建字节一致。

2026-10-23 用户确认历史版本仅留记录，二进制只保留最新已验收版本，替代原多版本保留规则。清理旧候选时保存版本、来源、大小、SHA-256、验收结果和移除时间；未正式发布的候选在任务记录或清理归档记录中追溯，不伪造正式发布条目。详细保留和晋级规则见 `release/README.md`。

依赖锁文件留在源码工程并纳入后续 Git 版本控制，不复制到每个历史版本文件夹。
