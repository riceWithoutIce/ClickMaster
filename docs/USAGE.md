# ClickMaster 0.1.0-rc.9 使用说明

本版是本地候选，尚未正式发布；本轮界面及限时功能仍需体验反馈。

1. 将 ZIP 完整解压到可写目录，运行 ClickMaster.exe。需要已有兼容的 Microsoft Evergreen WebView2 Runtime；本工具不自动下载、安装或提权。
2. 在“目标窗口”刷新并筛选 EXE、标题或 PID，必要时勾选“显示后台窗口”。选择并绑定具体实例；接收路由有歧义时在“窗口详情”确认。无窗口进程不能绑定，目标重启后重新绑定。
3. “输入方式”默认窗口消息，选择左键、右键或单键。鼠标坐标相对于排除标题栏及边框的客户区，默认中心；移动窗口不改变相对位置，缩放不自动比例定位。已支持 TapTapLoot 版本可另选专用 IPC，不使用键鼠/坐标参数。
4. “执行参数”设置最小/最大间隔，相等为固定，否则每次完整操作后随机等待。消息与IPC均为1～60000毫秒，默认2000/2000毫秒；1毫秒仅供极限测试，不承诺1kHz。这是操作完成后的额外等待，实际频率还受系统调度、传输与目标处理耗时影响。“永久”运行直到停止或保护触发；“限时”1秒～99时59分59秒，非法输入拒绝，不自动修正。
5. “执行一次”不受重复间隔/持续时间草稿影响；“开始”持续重复。开始前须注册F8成功，冲突则拒绝。随后准备3秒；专用IPC可在游戏前台或后台运行，保持非最小化，人工交互与自动效果可能叠加。消息模式仍以后台使用为目标。限时从准备结束计时，含操作与轮间等待。
6. 按停止、F8或托盘“停止”结束本轮。已发操作无法撤回；按下后仅原身份有效才配对释放，IPC清理本工具直接拥有的worker。到期不新发，剩余0不表示清理完成；清理未确认保持锁定，不算成功。

运行中参数锁定，显示已运行、剩余和本轮次数。消息次数为完整按下/释放投递次数；IPC次数为完整单帧写入的“已发送次数”，不是游戏计数。写入后停止或到期仍计入已经发送的一帧。结束原因、耗时、次数冻结保留；再次开始是新一轮，无暂停续跑。

最小化默认收起托盘并继续，设置可保留任务栏图标。关闭×提供收起/退出/取消；退出后停止，重启待命、不恢复绑定。仅最小化偏好持久化，其他为会话草稿。

底部“更多操作（…）→ 诊断信息”打开独立对话框，显示实际接收、按下释放回执、IPC阶段。可按 Escape 或关闭按钮返回原页面；页面标题旁的帮助按钮提供当前页说明。关键错误直接显示。实验预览在诊断内默认关闭；OVERLAY-001未显示问题未修复，不影响输入能力。

IPC失败诊断保留首次失败的阶段、固定原因及必要系统码，可区分原进程退出、窗口最小化、多实例、连接或写入问题；不保存原始路径或授权内容。授权之前退出等无法确认细节的情况会明确显示原因未确认，不把所有失败统一归为目标失效。清理未确认保持锁定，手动停止或限时仍按原规则优先处理。

IPC读取结果仅供传输层诊断，不代表游戏业务回执。单次路径仍在完整写入后短时观察最多200毫秒，再有界清理自有worker。重复路径在一次运行内复用一个已核验worker和连接，每帧保持原实例/唯一性/客户端写前核验，不等待或要求客户端读取确认，读取状态显示未确认；结束时清理连接。连接/写入失败、目标失效或清理未确认均停止，不重连、不重发、不回退。

已发送不保证游戏消费。极短间隔可能快于目标读取速度，管道背压时单帧写入最多等待2秒后停止；没有无界应用层发送队列。已完整写入的缓冲帧无法撤回，游戏可能在按下停止后继续处理它们，因此发送次数与游戏计数、写入频率与玩法频率必须分别观察。

## 性能诊断

从底部“更多操作（…）”打开“诊断信息”，点击“开始性能采集”。可在待命、连点过程中或收起主窗口时采集；每秒采样，60秒自动结束，也可点“结束采集”。采集只观察，不会启动、暂停或停止连点，也不改变目标或间隔。退出时有界收尾，异常退出的记录可能不完整。

结束后界面显示匿名文件名，请提供EXE同级`data/logs/`内同名`.jsonl`与`.txt`。不需要人工抄录CPU或计数。日志包括主程序CPU/内存、自有worker CPU与区间生命周期、执行参数/发送量、界面状态和阶段墙钟耗时。耗时不能相加当作CPU。复用worker可能跨越采集边界；若采集在运行开始后才开启，worker内部阶段未启用，或运行尚未结束，阶段摘要可能缺失；CPU仍以观察到的句柄区间为准，不把缺失阶段补零。

rc.6通过当前WebView的官方环境接口取得关联进程集合，记录匿名数量、类型、CPU、内存和覆盖状态。范围为同一用户数据目录的`webview-environment`，可能由多个实例或应用共享（`sharedPossible=true`），不含crashpad；不是本EXE独占资源，也不按全机进程名称猜归属。工作集求和可能重叠，不等于独占物理内存。接口不可用、访问失败、首次CPU基线、变化或过期会标`partial`/`unavailable`及空值，不能视作0。最多64进程、超过2.5秒的环境快照不用于资源归属；秒级快照可能漏掉短命进程和峰值。

采集期间可自行安排待命、执行、显示和收起。摘要按后端事实对照四种状态，混合切换区间标`mixed`、未知标`unknown`，未经历的组标`not-observed`；采集尾段不归入严格分组。收起后仍由后端刷新，不依赖前端轮询。不会为凑齐分组自动启动输入、切换窗口或抢焦点。建议每种所需状态保持数秒，CPU分项和缺失覆盖一起看，不把共享环境观测量冒称完整产品总占用。

采集默认关闭、不跨重启续采；只输出固定脱敏字段，不记录本机路径、真实进程标识、窗口标题、按键/坐标或授权内容。单次JSONL与TXT合计不超过1MiB，保留最多5套/5MiB，开始前只轮换本功能已完成且可识别的旧会话。未知、不完整、锁定文件保留；无法安全腾出预算时拒绝新采集，不影响连点。同目录多实例只允许一个实例持有诊断目录；写入失败不回退其他目录。阶段统计可能因中断/采集边界或测量争用不完整，报告会标明。

## 数据、移动、升级

数据跟随 EXE 同级 `data/`，不依赖启动工作目录，不回退用户目录。退出后移动整个文件夹；升级仅替换程序和资源、保留 `data/`。ZIP不带用户数据，不在运行中删除WebView目录或未知残留。正常IPC不保存逐帧历史，异常退出可能留下本轮槽位，不自动批量清扫；WebView缓存可能增长。

同目录多实例没有新增互斥保证，建议只运行一个副本。不同目录副本各用自身data；专用管道占用时失败且不重试，避免多个任务争用同一目标。

## 运行环境和系统提示

共享 Evergreen WebView2 不随ZIP分发，不提供完整离线运行时；缺失、版本不足或初始化失败时停止并使用原生错误提示，外部环境尚未实测。可从 [Microsoft 官方页面](https://developer.microsoft.com/microsoft-edge/webview2/) 获取运行时后手动重试；不要卸载其他软件共用的Runtime。

签名状态以配套来源清单为准；未签名时Windows可能提示，不保证无警告。仅使用已确认来源和SHA-256的包。详见[已知限制](LIMITATIONS.md)。
