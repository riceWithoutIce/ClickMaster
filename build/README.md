# 构建与暂存目录

本目录保存可重新生成的编译中间结果，不作为历史版本归档或唯一验收证据位置。目录说明与四个槽位的 `.gitkeep` 纳入 Git，实际输出默认忽略。

未来约定：

| 子目录 | 内容 | 保留方式 |
| --- | --- | --- |
| `frontend/` | 前端编译结果 | 固定输出路径，构建更新，不按时间另存 |
| `cargo/` | Cargo target、Rust 编译与 Tauri 打包中间结果 | 复用缓存，不为每个版本复制 target |
| `staging/` | 本次待验证/发布的一套产物 | 单槽位；下一次构建前处理旧暂存 |
| `logs/` | 当前构建日志 | 最多最近 10 次，单次按运行 ID 组织 |

首版构建跳过安装器打包，只将选定 EXE、必要资源与说明组成便携交付物后进入 staging，不复制整个 target 或依赖目录到 release。开发数据使用 `runtime/dev/`，验收运行数据位于 `verification/` 的独立运行目录，均不进入发布包。

需长期保留的失败记录、验收摘要或证据移交到 `aiwork/debug/` 或版本记录后，才属于可清理的普通构建日志；不能因 Git 忽略就认定任意文件都可删除。

当前未生成构建产物，未实现缓存/日志清理脚本。Cargo/npm 自身的全局下载缓存不因本约定而被移动或清理，其策略在工程配置时明确。

## 2026-10-23 清理与保留规则

以上“当前未生成”描述为早期基线；现在已有构建与候选。用户确认工作目录收敛为源码文档、必要证据和最新候选：

- 历史 EXE、ZIP 和解压副本归档版本、来源、哈希及验收结果后删除，只保留最新已验收版本；不另建整套历史备份。
- `verification/` 保留关键报告、失败证据、来源清单和必要脚本，清理重复工程、依赖、编译输出和旧测试 EXE；未解决问题只保留必要复现证据。
- 旧验收副本的 `data/` 提取必要配置和问题日志后，可清理无用 WebView 缓存及测试数据；仍在使用的数据保留。
- 共享 Cargo 编译输出、下载缓存和开发依赖暂留到正式包完成，再决定深度清理，不为每个历史任务保留独立缓存。
- 当前 rc.9 是最新已验收候选，正式包完成验收及替换后也可淘汰。主要交付物只保留一份 ZIP 和小型来源/校验记录，运行验收副本不作为永久备份。
- 不使用 `git clean` 批量处理当前未跟踪的源码与任务记录。按具体保留/删除清单执行，文件占用则跳过并记录，不结束外部进程。

本次只记录约束，未执行清理；发布数量与晋级顺序以 `release/README.md` 为准。
