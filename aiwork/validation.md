# 最小验证与验收记录

当前状态：未执行。以下为验证方案，不是通过证据。

## 证据分层

| 类别 | 能证明什么 | 不能据此推断什么 |
| --- | --- | --- |
| 源码检查 | 实现中使用的 API、绑定检查及停止逻辑 | 实际运行正常或游戏兼容 |
| 构建结果 | 指定环境下代码可构建 | 后台输入有效 |
| 可控测试窗口 | 消息内容、按下/释放顺序及目标选择符合预期 | 具体游戏接受输入 |
| Windows API 返回与日志 | 调用成功或失败、发送时间和错误信息 | 目标玩法已响应 |
| 目标人工观察 | 指定目标、输入方式及环境下的实际响应 | 其他输入方式、其他应用或最小化场景也兼容 |

## 测试前记录

- 工具版本或可归属的源码快照、构建方式及运行环境。
- 目标 EXE 名称、PID、进程实例标识、窗口句柄与标题。
- 目标是否非最小化、输入方式、按键或客户区坐标、重复间隔。
- 全局停止热键及其注册结果。
- 当前工作窗口与输入隔离观察方法；避免记录无关个人内容。

## 验证顺序

1. 选择并绑定目标，核对显示的 EXE、PID 和窗口。
2. 配置一次鼠标左键测试。确认真实鼠标位置后，切到其他工作窗口，再投递一次输入；分别记录游戏响应、工作窗口输入、鼠标移动和焦点情况。
3. 对鼠标右键和单个键盘按键分别执行同样的一次测试。安排触发方式时，确保实际投递发生在游戏失去前台焦点之后。
4. 至少一种输入方式有效后，选用该方式执行低频重复，记录观察时长、配置间隔及实际响应。
5. 测试停止按钮和全局停止热键，核对停止后没有新一轮投递，并单独记录已入队消息的后续处理。
6. 在重复期间关闭目标，确认停止；目标重新启动后，确认不会自动重新绑定或继续发送。
7. 检查热键注册失败、窗口失效和客户区坐标越界时的提示与处理。

若单次测试均无效，记录每种方式的结果并停止，不进入重复测试，不自动换用全局模拟输入、驱动或注入。

## 通过条件

- 至少一种输入在游戏保持后台、非最小化时持续触发玩法响应。
- 当前工作窗口没有收到工具产生的额外输入。
- 真实鼠标没有被移动，游戏没有被工具主动激活。
- 停止后不再开始新一轮输入；目标退出后停止执行。
- 其他 EXE 的选择能力有可控窗口或其他实际目标的选择证据；不据此承诺其玩法兼容。
