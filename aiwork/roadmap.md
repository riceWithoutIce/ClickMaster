## M1：独立最小验证工具

- [ ] 在本项目内实现独立工具，确认源码、构建产物与日志的目录边界。
- [ ] 实现窗口枚举、选择和具体实例绑定。
- [ ] 实现客户区中心、手动 X/Y 坐标及坐标校验。
- [ ] 实现左键、右键、单个键盘按键的单次测试。
- [ ] 实现低频重复、开始/停止和全局停止热键。
- [ ] 实现目标退出、窗口失效和绑定身份变化后的停止。
- [ ] 提供必要状态与日志，明确投递成功不等于游戏响应。
- [ ] 完成对应构建及可控测试窗口验证，记录实际执行的检查。

完成条件：工具具备执行 `validation.md` 中人工目标验证的能力，源码/构建证据已记录。此阶段完成不等于目标游戏兼容。

## M2：后台兼容性验证

- [ ] 选择实际目标，记录进程实例、窗口、环境和工具版本。
- [ ] 切换到其他工作窗口，分别测试一次左键、右键、键盘输入。
- [ ] 至少一种输入有效后，再用该输入测试低频重复。
- [ ] 验证工作窗口不受额外输入影响、真实鼠标不移动、目标不抢焦点。
- [ ] 验证停止、热键停止和目标退出；按停止语义记录已入队消息。
- [ ] 形成按目标和输入方式区分的兼容性结果。

完成条件：目标在后台持续响应至少一种输入，并满足隔离与停止要求。

停止条件：单次后台输入均无效或出现干扰当前工作窗口的情况时，停止重复验证、保留证据并返回讨论。不自动更换输入技术。

## M3：第一版交付

- [ ] 依据验证结果完善必要的配置、状态展示和错误提示。
- [ ] 按确定的方式构建、打包，记录版本与运行前提。
- [ ] 提供目标绑定、输入配置、停止和兼容性限制的使用说明。
- [ ] 核对冻结需求，列出已验证项目、未验证项目和后续事项。

完成条件：可交付产物、使用说明与真实验收证据一致；发布范围内的兼容性承诺有证据支持。

## 推进规则

已推进到用户授权的技术选型、工程目录、版本归档设计与 workflow 文档落地阶段。后续实现按用户指令和 [协作工作流](workflow/README.md) 推进。默认参数未定不改变已冻结功能；功能范围发生变化时更新需求与日志。
