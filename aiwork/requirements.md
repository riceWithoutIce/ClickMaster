## 目标与使用场景

开发 Windows 后台连点工具，绑定用户选择的应用窗口，在用户操作其他软件时向目标持续发送重复输入。目标窗口允许保持非最小化。

`TapTapLoot.exe` 仅是示例目标，不得写死为唯一支持程序。后台消息对各目标应用的实际兼容性必须分别验证。

2026-10-21 用户补充确认：软件应为轻量级。选型需比较发布体积、运行时依赖与运行开销；具体体积、内存、CPU 和启动时间预算尚未冻结，见 `technology-selection.md`。

同日用户补充 UI 方向：需要考虑视觉风格，例如圆角界面与 UI 动效。将视觉定制能力纳入技术选型；具体布局、动画范围、窗口外框与性能预算待设计明确，见 `ui-technology-selection.md`。

## 功能范围

| 编号 | 需求 |
| --- | --- |
| R01 | 从当前运行的应用窗口列表选择目标，显示窗口标题、EXE 名称和 PID，支持选择不同 EXE 对应的窗口。 |
| R02 | 绑定具体进程实例及其窗口，不能仅按进程名匹配；目标重启后必须重新绑定，不自动跟随同名进程。 |
| R03 | 输入方式提供鼠标左键、鼠标右键、单个键盘按键，每次选择一种执行。 |
| R04 | 每次输入均为完整按下与释放，不包含长按。 |
| R05 | 提供单次输入测试，左键、右键、键盘分别验证。 |
| R06 | 支持配置重复间隔。 |
| R07 | 鼠标支持客户区 X、Y 坐标，默认可使用客户区中心；键盘模式不使用坐标。 |
| R08 | 提供开始、停止按钮与全局停止热键；热键注册失败时禁止开始，并显示原因。 |
| R09 | 目标窗口退出或失效后停止；运行前及发送时应校验绑定身份，避免向替代进程或无关窗口发送输入。 |
| R10 | 记录发送结果、停止原因和异常，区分投递成功与玩法响应。 |

## 输入与坐标边界

- 优先采用 Windows `PostMessage`，向绑定目标发送鼠标或键盘消息。
- 鼠标发送对应左键或右键的按下、松开消息，携带客户区坐标。
- 键盘发送一个所选按键的按下、松开消息。
- 不移动真实鼠标，不主动激活目标窗口，不注入 DLL 或代码。
- 后台消息无效时停止调查并记录结果，不自动回退全局 `SendInput`，不擅自升级为驱动或注入方案。
- 客户区坐标排除标题栏和边框；窗口移动后仍对应内容区域内的同一位置。发送前校验坐标是否在客户区内。
- 窗口缩放后的比例定位不属于第一版范围。

## 停止语义

停止后不再开始新一轮输入。已成功入队的 Windows 消息无法撤回；已发送按下的操作应在绑定目标仍有效时完成配对释放。不得为了释放而向失效或身份不匹配的窗口继续投递。

停止验收分别记录停止请求时间、最后一轮投递以及目标应用观察结果，不能将停止后才被游戏处理的已入队消息误记为新一轮发送。

## 排除项

- 长按、组合键、多步脚本、同时执行多种输入方式。
- 最小化兼容承诺，以及任意游戏都有效的兼容承诺。
- 全局模拟输入回退、驱动、DLL 或代码注入。
- 自动启动目标 EXE、游戏重启后自动重新绑定。
- 接入 Unity 项目或修改原来的 MouseClickTool。
