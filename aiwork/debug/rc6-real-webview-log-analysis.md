# rc.6 真实 WebView 性能日志分析

日期：2026-10-23。分析对象为用户提供的 `build/staging/TASK-010-WEBVIEW-METRICS/data/logs/`，只读完成，原始 JSONL/TXT 未修改。

## 日志范围

- 版本 `0.1.0-rc.6`，性能采集约 60.003 秒，59 个样本，16 个逻辑处理器。
- 本目录只有一组 JSONL/TXT，内容是 `channel=ipc` 且采集开始时已经处于执行状态；没有第二组待命采集。
- 严格状态分组为：`running-visible` 22.145 秒、`mixed` 2.003 秒、`running-hidden` 35.142 秒。`idle-visible`、`idle-hidden` 均 `not-observed`。
- 采集期间发送计数为 51（摘要），样本增量覆盖 50 次，首样本前已有运行上下文，末段还有尾部发送；不能把样本增量 50 当成完整会话发送数。

## WebView 资源

官方关联环境在 58 个样本中可用，首个样本为 `partial`，原因是首次建立 CPU 基线；每次列出并打开 5 个进程，类型固定为 browser 1、GPU 1、renderer 1、utility 2，未出现持续缺失或列表膨胀。环境范围是同一用户数据目录，可能由多个实例或应用共享，不是 ClickMaster EXE 独占资源，也不含 crashpad。

关联 WebView 工作集约为 361.8–371.9 MiB，平均约 366.4 MiB；专用内存约为 181.6–191.7 MiB，平均约 185.0 MiB。工作集之和可能重叠，不能直接当作独占物理内存，但这说明 WebView 环境是本次内存占用的主要组成部分。

## CPU 结果

采样区间内主程序 CPU 1.343750 秒，worker CPU 约 2.187500 秒；关联 WebView 进程 CPU 约 2.390625 秒。按 16 个逻辑处理器折算，三者合计约 0.624% 的整机平均 CPU。摘要中的主程序整机平均为 0.140%，与样本区间一致。

按状态看，`running-visible` 三部分合计约 0.604% 整机平均 CPU，`running-hidden` 约 0.636%。两者差异很小；这组日志没有证据表明收起到托盘会显著降低 CPU，也没有显示 WebView 在后台持续高占用。

这不能排除用户在任务管理器中看到的瞬时高峰：本次是 1 秒采样，且只覆盖 ClickMaster、其自有 worker 和关联 WebView 环境。其他进程、短于采样周期的峰值以及共享 WebView 中其他应用的消耗不在可归属范围内。

## 主要瓶颈：IPC 连接等待

50 个 worker 的阶段统计显示：

- `connect` 累计约 46.980 秒，单次最大约 953.190 毫秒，平均约 939.6 毫秒；
- `read-observation` 累计约 3.586 秒，平均约 71.7 毫秒；
- 完整校验约 0.845 秒，父/worker/程序集哈希合计约 0.590 秒；
- 实际写入累计约 0.216 毫秒。

因此，100ms 最小间隔并没有产生 10 次/秒的发送。摘要显示约 0.85 次/秒，50 个样本发送增量覆盖约 0.84 次/秒；主要原因是每次发送都要新建 worker 并等待 IPC 连接，连接等待远大于配置间隔。这个问题首先表现为发送吞吐和响应频率不足，连接等待本身主要是墙钟阻塞，不等于同等比例的 CPU 消耗。

## 结论与边界

本次日志支持以下判断：

1. WebView 资源已成功采集，约 366 MiB 工作集是本次可见的主要内存来源，但归属可能共享。
2. 本次可归属 CPU 平均较低，性能问题不能归因于持续 CPU 满载。
3. IPC 每次重新连接是当前最明确的性能/吞吐瓶颈，解释了 100ms 配置下实际只有约 1 秒一次的发送。
4. 只有 IPC 运行日志，尚不能完成待命与运行的差值比较，也不能证明托盘状态对性能的长期影响。

本记录不修改 IPC 架构或生产代码。后续若继续调查，应先做一份不启动连点的待命采集，再决定是否单独评估连接复用；连接复用属于新的架构变更，需要另行对齐和授权。

## 人工现象补充

用户反馈截图显示：运行期间界面持续显示“等待 IPC 连接”，连接和单帧写入仍为未确认，鼠标出现 Windows loading 光标。该现象与日志中每轮约 940ms 的连接等待相符。

源码只读核对显示连接监督循环运行于独立 `ipc-supervisor` 线程；因此当前证据可以确认传输等待，但不能单独证明 loading 光标来自 Tauri UI 线程阻塞。UI 响应性需要另做受控测量。
