# Coder 开发与交接

## 实现与自测

1. 阅读任务契约、冻结需求及相关现有文件，确认当前本地改动；保留无关文件和用户配置。
2. 在授权范围内实现。发现契约矛盾或阻塞时记录原因，经主协调者对齐；可独立推进的工作继续完成。
3. 执行与本次改动相称、契约约定的检查。文档改动检查链接和一致性；输入调度、绑定、停止等核心行为需有对应验证。
4. 如实记录命令、环境、结果、失败和未执行项。编译、消息投递、可控窗口、游戏实测、发布证据分别表述。
5. 按 [脱敏约定](sanitization.md) 检查修改文件及附带证据，再填写 [交接模板](templates/coder-handoff.md)，说明修改、限制、证据与验收入口。

不为了完成任务擅自修改需求、引入禁止的输入方案、覆盖本地改动、提交代码、发布或执行无关清理。

## 稳定快照

- 快照须明确对应哪一份代码、配置和锁文件，以及本次修改清单。
- 已有 Git 时记录提交标识和未提交差异；单独一个 HEAD 不能代表包含本地改动的快照。
- 未初始化 Git 时，可用任务内快照编号、相关文件清单和 SHA-256 建立可归属性，不因此自动初始化 Git 或创建提交。
- 提交交接后停止修改被验源码。Verifier 开始前及结束时核对快照；若发生变化，记录差异，原结论不能直接覆盖新状态。
- 测试输出不计为源码变更；对被验配置和锁文件的修改仍属于快照变化。

快照信息保存于任务记录，不新增 `src-old`、按日期复制的源码目录或整份构建缓存备份。

## 修复交接

用户决定当前修复后，主协调者明确原 finding、允许修改范围和紧邻回归，再由 Coder 修复并自测。交接引用原 finding 编号、修复内容、新快照和相关检查；延期项保持原处置，不趁修复扩大范围。
