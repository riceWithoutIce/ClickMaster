## 命令契约

以下为拟定统一入口，具体实现在 Coder 交接中列出。所有命令从仓库根运行，开发脚本将缓存与输出约束在本项目内：

- `npm run dev`：启动 Tauri 桌面开发流程，内部启动 Vite；不是仅打开网页。
- `npm run typecheck`：执行 Vue/TS 类型检查。
- `npm run build`：生成前端生产构建到 `build/frontend/`。
- `npm run build:desktop`：生成 x64 桌面生产程序，禁止打包安装器；统一准备 Cargo 进程环境，并采用锁定依赖构建。
- `npm ci`：仅在隔离副本运行，使用锁文件及约定的 npm 缓存参数；初次生成锁文件由 Coder 处理。

若命令接口需调整，必须保持对应功能与输出边界，并在交接中明确实际入口，不能留下不可执行的文档命令。没有业务实现时不编写仅复刻模板的单元测试；类型检查、可重复构建、真实 IPC 与原生窗口运行是本轮主要证据。

## 运行验证范围

最初允许任务内运行本工具与开发辅助进程。用户随后明确“我来进行验收，因为我还在操作电脑”，此后原生桌面验收完全移交用户；agent 不再启动本工具或开发服务器，不操作、截图、激活、最小化或关闭窗口，不以其他自动化手段替代。已运行的原验收窗口保持原状。非 UI 构建和纯文件测试继续在项目内隔离执行，不触及用户运行数据或外部进程。

正常窗口交互应留有人工或工具的实际操作记录。无法自动操作时，将具体条目标为未执行并列出人工检查步骤；未完成原生窗口验证前，不宣称本任务无条件验收通过。

人工验收入口为 `build/verification/TASK-001/coder/final/ClickMaster.exe`，哈希见交接；此前已运行的 `coder/runtime/ClickMaster.exe` 哈希不同，旧产物人工结果仅绑定原产物，不能不加说明地转为最终产物通过。

Windows 11、后台输入、全局停止、目标退出、正式便携包发布与缺失 WebView2 的处理流程不属于本轮执行范围，保持未执行，不能因 AC-01–AC-14 通过而标记为已通过；本轮不可写数据目录的原生提示仍属 AC-08 范围。

## 结果与停止

Coder 与 Verifier 按 PASS / FAIL / NOT RUN / INSUFFICIENT EVIDENCE 记录每项结果。Verifier 不修源代码，源码快照冻结后再正式验收。

发现失败保留脱敏证据，不重复安装工具或自动扩大修复范围。原 blocker 关闭、约定检查通过且延期项明确后结束审核；findings 由主协调者一次性返回用户决定。
