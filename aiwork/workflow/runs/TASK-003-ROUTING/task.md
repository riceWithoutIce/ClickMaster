## 产品契约

1. 仍由原窗口候选token选择具体绑定窗口，身份为 HWND/PID/进程创建时间/线程，并保留绑定代次。分离输入接收窗口的身份/选择状态/代次，不让前端提供任意HWND/PID作为发送目标。接收目标必须是绑定自身或该绑定窗口内经过后端校验的候选，不跨树或按名称追踪其他实例。
2. 绑定后识别明确的宿主结构（ApplicationFrameWindow内CoreWindow内容），无需限定计算器EXE。唯一可验证内容子窗口自动选择；多个符合候选时阻止发送，给出后端token候选供用户明确选择，显示类/进程名/PID及必要尺寸区分，不默认第一个。普通窗口无这种结构时继续向绑定自身发送；宿主结构查询失败/存在不可验证候选时明确不可用，不静默回退宿主。不得推广成对任意子控件盲猜接收者。可提供显式“绑定窗口自身”选择便于用户控制，但不得在内容失效后自动回退。
3. 接收路径选择发生在绑定/明确刷新或用户选择阶段，输入捕获已确认路径快照。后台轮询只复验原路径，不在子窗口消失、重建、父子关系变化或进程退出时自动选新子窗口。此时阻止新输入、取消未发送任务，清楚要求重新绑定，不能因仍有宿主而显示输入可用。允许保留宿主绑定以便用户看见失效原因，但必须无接收目标且禁用单次；若选择整体解绑也可。重新绑定/接收者切换取消旧待执行输入。显示刷新或候选列表刷新不得随意改选原有效接收者。
4. 每次发送按下及释放均复验绑定、接收目标及父子关系、原代次。跨进程CoreWindow同样验证进程创建时间/线程/所属关系。取消或退出已投递按下时，只向仍有效原身份补一次释放；失效则报告partial，不向替代窗口、宿主或新绑定补发。锁序明确沿用input→targets，避免与overlay退出/停止互等。
5. 键盘映射使用实际接收窗口线程的键盘布局，向实际接收窗口发送固定既定WM_KEYDOWN/UP语义。左右键按用户选择构造；所有鼠标位置（默认中心/自定义）先在绑定窗口客户区像素中计算和验证，再在同一明确DPI上下文中转换到接收窗口客户区（如ClientToScreen/ScreenToClient或MapWindowPoints）。检查绑定尺寸、输入非负整数、映射后接收客户区范围、最终有符号16位；任何失败不截断、不夹到边缘、不换窗口或改用真实鼠标。接收自身时行为保持。移动/缩放后发送时重新计算，不做比例定位。
6. 界面保留侧栏/二级路由及紧凑布局。目标页和必要运行摘要分别显示“绑定窗口”“输入接收窗口”，后者包含实际EXE、PID、类和自动/手动/自身/待选择/失效说明。单次按钮受接收目标状态约束；歧义选择可理解，不暴露实现原始句柄。结果仍为已投递、目标是否响应待确认，不因自动路由冒称玩法成功。运行结果最好保留该次接收窗口摘要，避免换绑后让旧receipt看似发给新目标。
7. 保留3秒倒计时、约50ms配对、42键白名单、单任务、防重入/取消/解绑/退出及minimize拒绝。真实鼠标不移动、目标不激活，不增加WM_CHAR/SendInput/设备状态/注入/驱动/权限提升或自动回退。自动路由不承诺所有UWP、游戏或最小化兼容。
