## 目标

- 专用 IPC 持续重复时，优先在一次运行内复用已核验的 worker/连接，避免每一帧重新创建 worker、建立命名管道和等待连接。
- 保留目标进程实例、支持版本、程序集/EXE 身份、客户端 PID、授权、单帧写入、停止、F8、托盘、退出和清理保护。
- 将固定/随机重复间隔的可输入下限改为 1ms，上限仍为 60000ms。1ms 是极限测试输入，不承诺 Windows 调度或目标游戏达到 1kHz；实际间隔和吞吐必须记录或如实说明。
- 调查并改善运行期间的界面响应性。连接等待不能把 Tauri UI 线程长时间同步阻塞；UI 应能显示状态并允许用户停止。

## 范围

允许修改专用 IPC 运行链、受控 worker/pipe 生命周期、重复调度与间隔校验、对应 UI 参数提示、测试/说明/版本和本地候选打包。持久连接是否被目标协议接受，先用隔离接收器验证；若连接只支持单帧，记录证据并停止扩展，不自动切换到全局输入或其他注入方式。

连接中断、身份变化、授权失败、目标退出、停止或退出时必须 fail-closed，清理自有资源；不自动回退消息模式、不使用 DLL/驱动/SendInput、不自动重试隐藏问题。消息模式保持原语义。

## 排除项

- 不修改窗口枚举/绑定、客户区坐标、覆盖层、WebView 诊断采集、托盘产品规则或未处置 V008-01。
- 不承诺 1ms 的真实游戏响应频率，不以单次 fixture 吞吐替代真实游戏验收。
- 不引入新依赖、运行时安装、全局配置、提交、推送、正式发布或历史清理。
- 不自动启动普通 UI、游戏、全局热键或改变用户焦点；真实 TapTapLoot 与鼠标 loading 现象留给人工验收。
