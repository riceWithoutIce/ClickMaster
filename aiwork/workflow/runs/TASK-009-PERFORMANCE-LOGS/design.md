# 性能诊断采集契约

状态：待实现。这里的预算属于本任务范围，不代表现有版本已具备。

## 操作与生命周期

- 默认关闭，不持久化为下次自动开启。现有诊断区域提供“开始性能采集”“结束采集”，显示已采时间和固定60秒上限。
- 用户可在待命或连点时开启，采集期间可自行开始/停止任务、收起/恢复主界面。采集不改变连点状态，60秒仅结束采集，不能停止连点。
- 同一程序实例最多一个采集会话；重复开始拒绝，结束可重复调用。退出执行有界收尾，日志失败不阻断原停止/退出及IPC流程。异常退出保留有界部分文件，不谎报为完整报告。

## 自动采集内容

| 内容 | 口径与边界 |
| --- | --- |
| 会话信息 | schema版本、应用版本、逻辑处理器数、单调相对时间、结束原因；不写绝对时刻或机器名称 |
| 任务上下文 | 待命/准备/执行/停止，通道，间隔上下限、永久/限时及限时秒数，已发送次数、实际每秒发送量；不包含目标身份或输入内容 |
| 主进程资源 | 累计CPU差值、按逻辑处理器归一的整机CPU百分比、工作集和专用内存；明确区间与缺失，不把查询失败写0 |
| 自有worker | 原持有进程句柄归属，匿名编号、创建/退出数量、生命周期、CPU累计；退出后仍收集CPU，不依赖每秒枚举捕获短命进程，不重叠累计 |
| WebView2 | 仅可证明属于本实例的子进程，分组CPU/内存及覆盖限制；归属不可靠就记unavailable，不能按进程名合计全机WebView2 |
| 阶段耗时 | worker启动/授权、EXE与程序集哈希、完整目标核验、连接、写入、读取观察与清理的次数/总耗时/最大耗时，固定词汇；重叠阶段注明嵌套，不能相加冒称CPU或端到端时间 |
| 界面状态 | 主界面可见/最小化/托盘收起等本工具状态，不记录其他窗口焦点；状态未知明确标注 |
| 异常 | 固定失败阶段/原因、可选数值系统码、统计缺失/报告不完整/写盘失败，不输出原错误字符串或路径 |

采集边界内创建的worker统计完整生命周期；采集开始前已存在或结束时仍运行的worker标注边界截断，可用CPU只计采集内区间，不能把全部生命周期CPU错误归入会话。不能为等其退出延长60秒或终止它。阶段统计同样注明覆盖范围。

每秒采样一次，使用实际单调时间差；采样延迟不补采过去的虚构样本。CPU与墙钟耗时分别解释：阶段等待长不等于高CPU，阶段耗时只用于定位候选成本。保留CPU秒与分母以便复算；短命WebView进程或查询缺失不得承诺全覆盖。

## 开销与文件预算

- 关闭时不创建采样线程、日志文件或额外进程枚举，测量点只做必要开关判断。不将记录挂到现有10ms循环写盘。
- 开启后内存有界汇总，阶段只存计数/汇总而非每帧明细；最多每5秒批量写出，并在采集结束汇总。记录写入失败或队列丢弃，不无限排队，不等待慢盘阻塞输入线程。
- 一个会话使用一个JSONL文件（记录类型区分header/sample/stages/summary）加一个简短TXT摘要，统一匿名随机文件名，累计最多1MiB/会话，达到预算提前结束采集并标明原因，不停止连点。
- 仅本功能已完成且可识别的会话最多保留5套、合计5MiB；开始前按既有会话顺序轮换，不能删除活动/未知/不完整文件或任何旧IPC证据。若无法安全腾出预算，拒绝新采集并提示，不突破上限。
- 同目录多实例、同名冲突、文件被占用不得互删会话；使用原子独占创建和可确定的日志目录所有权/互斥。若无法建立安全所有权则本次采集不可用，原程序继续工作。
- 生产位置为EXE同级data/logs/；开发、测试、便携验收副本仍位于项目内。无外部临时文件、自动压缩、外传或自动打开资源管理器。

摘要给出采集覆盖、参数、CPU分项及可用性、发送量、worker创建/退出、阶段汇总、记录丢失/文件预算状态和固定限制说明。用户无需手工记录数字，将JSONL和TXT一起提供即可分析；耗时统计不能冒充采样剖析器的CPU热点归因。
