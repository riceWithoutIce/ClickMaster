# TapTapLoot IPC 单次数量 1 验证

日期：2026-10-22。授权：用户在只读分析后同意先对齐 IPC 影响；主协调者说明单次、独立工具、唯一实例/客户端身份检查、已有同名管道拒绝、后台非最小化、超时即停、无重试/全局输入、结束仅清理自有资源。用户回复“好 那我们继续”，批准本轮限定 POC。当前不授权产品接入、循环运行、游戏修改、提交或发布。

## 目标与基线

- 基线：本版本游戏 PostMessage 键鼠均未取得响应；静态发现 GlobalKeyHook 系统状态轮询和已有 TypingFarmer 联动客户端。见[只读分析](../../../debug/taptaploot-input-mechanism-analysis.md)。
- 假设：已有本地 IPC 客户端能够连接诊断服务器，接收一次数量 1，并在后台转换为玩法事件，无需系统键鼠输入。
- 本次只证明单次 IPC 传输和可观察效果，不承诺任意游戏、特定按键语义、统计/成就等价或稳定长期支持。

## 实现与执行边界

- Coder 唯一脚本写入者：`build/verification/TAPTAPLOOT-IPC-POC/coder/`。交接放本任务目录 `coder-handoff.md`，附精确文件清单及 SHA-256。不改产品或既有只读分析脚本/结果，不下载依赖。
- 使用现有 PowerShell 7/.NET，在编译/子进程前设置 TEMP/TMP/TMPDIR 为项目内路径。脚本/中间产物/证据均在仓库内。持久输出不含真实 PID/HWND、路径、标题、用户名、异常堆栈或截图。
- 默认运行纯自检；必须显式 `-RunOnce` 才接触真实游戏/端点。Coder/Verifier 不得运行该模式，不建/连真实联动管道、不发游戏输入，不启动 UI。
- 唯一精确名称 TapTapLoot 进程，记录仅匿名身份；主程序集 hash 必须匹配只读分析版本 `BC5318AC557E4039ADCCAE8D79EAF66F6C0200D18FC043FD2AA632F6513C35B8`。保持原进程对象/必要句柄，校验创建时间、存活及窗口归属，不跟随重启或替代实例。
- 目标实际 UnityWndClass 客户窗口必须唯一、可见、非最小化、后台。识别/校验只读，不激活、显示、移动、关闭目标，不注入、不读取游戏进程内存、不记录键鼠输入。
- 只使用 `TapTapLootxTheFarmerWasReplaced` 本地联动名，不碰 BongoCat buff 通道。使用 Windows first-instance 原子独占创建，maxInstances=1、当前用户限定、拒绝远程客户端（如现有受支持接口可用）。已有端点/权限失败立即停止，不探测连接已有端点、不抢占/反复重建。
- 服务器与游戏客户端方向兼容（游戏 InOut），连接等待最多 20 秒。核验 GetNamedPipeClientProcessId 与原游戏 PID/创建时间及窗口状态一致后才允许写入。任何不符立即关闭本诊断自有管道，不能换客户端重试。
- 发前保留约 5 秒观察准备期（脚本可在建立端点前统一倒计时）；游戏变前台或状态失效则拒绝发送。使用同一缓冲区一次 WriteAsync 发送四字节 `00 02 31 00`：大端字节长度2 + UTF-16LE字符1。写入预算2秒，不重试、不补发、不使用无期限 drain/flush；发生部分/未知写入不能报未发送或重发。
- 发后最多约3秒只读观察游戏是否前台；记录仅匿名采样摘要，不记录用户按键/鼠标坐标或其他前台标题。瞬时采样不等于全程隔离保证。
- 用原子 attempt receipt 阻止同一任务再次执行真实尝试；先写最终回执再退出，异常也需记录已知发送阶段。整个操作有界，不因失败自动重跑。结束 dispose 服务器/本次目标只读句柄，仅释放自己拥有的资源，不退出游戏或其他工具。
- 日志阶段明确区分 preflight、listening、client-verified、write-attempted、write-completed、closed；传输成功不能冒充游戏消费或玩法响应。连接无回执，不声称应用确认。
