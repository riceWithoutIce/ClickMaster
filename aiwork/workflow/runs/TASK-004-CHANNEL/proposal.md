# 主程序通道集成任务建议

日期：2026-10-22。状态：讨论草案，待用户确认交付范围并授权开发；不代表已开始实现。

## 已确认基础

用户已确认[通道选择交互](../../../input-channels.md)。独立IPC测试EXE的单次和低频游戏响应人工通过，但未替代正式Tauri产品、停止/关闭/隔离验收。正式技术栈仍为Tauri + Rust + Vue/TypeScript。

## 建议分轮交付

本轮先完成主程序通道选择与IPC单次测试：

- “输入方式”页面顶部增加通道下拉；默认窗口消息，IPC需用户明确选择。运行期间锁定通道、参数及目标变更，前后端均校验，不自动切换或回退。
- 窗口消息保留现有左右键、键盘、坐标和内容路由；IPC隐藏这些无关设置，不受窗口消息内容路由就绪条件误阻塞。顶部接收对象及结果随通道显示，不把IPC客户端称为内容子窗口。
- IPC启动前及发送时核验具体绑定实例、支持版本、窗口状态和管道客户端身份；名称匹配不足以允许发送。不跟随重启，不为核验自动建立管道或触发游戏。
- 建议单次统一沿用主程序3秒准备，每次IPC发送数量1，区分连接、写入、读取及实际游戏响应。不把独立工具5秒准备直接移入产品。
- 支持准备/连接/读取期间停止；实际退出程序先取消并释放自有资源。收起到托盘仍是窗口行为，不等于退出；不能因托盘操作丢失任务状态。消息模式原取消/配对释放行为保留，在途IPC帧不可撤回。
- 通道切换保留用户本次会话中的消息模式参数，不将IPC隐藏参数当作发送内容。建议本轮不新增跨重启通道记忆，启动仍默认窗口消息；现有配置文件及托盘偏好兼容。
- 保留重复“开始”入口为未开放。本轮不新增重复调度或全局停止热键，不修延期覆盖层，不接入其他游戏适配器。

下一轮再独立对齐两通道共用的重复调度、默认间隔/上下限、全局停止热键及其冲突处理；独立测试器的2秒、最多5次和F8不自动成为产品参数。

## 实现前需核定

实现契约须明确Rust侧IPC和可取消阻塞处理、超时/清理边界、原生drain隔离方式、逐实例身份与版本依据。沿用已验协议和行为，不直接假定C#测试器代码可原样接入；若拟增加运行时/依赖或改变分发，先返回对齐。所有构建、缓存、临时及测试输出在项目内，运行数据跟随实际EXE的data目录，记录脱敏。

## 建议验收

- Coder：两通道分支、忙碌锁定、失效拒绝、停止/超时和配置兼容的必要自测与构建；不自动打开游戏或发送。
- 稳定快照后独立Verifier只读验收，集中报告，不在开发中追加修复。子agent安排遵循用户最新批准范围，不默认启动。
- 用户：主程序IPC单次游戏响应，停止/关闭/目标退出，工作窗口输入、鼠标及焦点隔离；消息通道既有流程做紧邻回归。源码/构建通过与真实桌面验收分别记录。
- 仅本地测试包，不提交、推送、发布或清理历史证据。
