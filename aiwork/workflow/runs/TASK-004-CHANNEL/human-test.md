# 主程序通道集成人工验收

状态：待稳定测试包和独立审核完成后由用户决定开始；本文件不是运行记录。主协调者不自动打开EXE、查询游戏或发送。

## 最短流程

1. 使用本任务验收记录最终指向的测试包，自行关闭旧ClickMaster后打开新包。保持游戏可见且非最小化。主程序启动应待命、默认窗口消息，不自动连接或触发游戏；无需启动独立IPC测试EXE，两工具不要同时测试同一管道。
2. 目标页筛选并绑定具体TapTapLoot实例，输入方式页选择“TapTapLoot 专用 IPC”。兼容性不支持时应显示原因并禁止测试，不自动变成窗口消息。不需设置数字键或坐标。
3. 点击“单次测试”，在3秒准备期间切换到其他工作窗口，游戏保持后台可见。观察倒计时结束后的游戏变化；游戏也会将用户点击按钮或操作键鼠计数，不能把这些真实输入引起的变化当作IPC效果。
4. 分别记录主程序连接/写入/读取结果与可见游戏响应。读取完成只证明传输数据读走，不代表所有玩法、统计或成就等价；没看清就反馈没看清，不自动重发。
5. 可在准备或等待期间点击“停止”，观察状态能结束且设置解锁；已发出的在途帧不能撤回。运行期间通道、参数和目标变更应被阻止。
6. 按需分别验证退出程序、目标退出和收起到托盘：实际退出应取消自有任务，目标退出应停止且重启需重新绑定；收起应保持可还原状态。尚未执行的场景保留待验，不为完成清单自动重启游戏。
7. 停止后切回窗口消息，应恢复本次会话原键鼠参数。若进行消息路径回归，绑定计算器、确认现有内容路由，单次数字键应仍可用；不对TapTapLoot重复尝试已知无效消息路径。

## 分项反馈

请分别反馈实际做过的项目：通道界面、主程序IPC游戏响应、停止、退出、目标失效、托盘、计算器消息回归、工作窗口无额外输入/鼠标不移动/游戏不抢焦点。遇异常停止并保留EXE同级data，不自行换通道或增加次数。

本轮重复“开始”和全局停止热键尚未开放，不使用独立测试器的F8说明作为主程序承诺。数据位置及运行前提以本任务实际交付说明为准，不回退用户目录，不自动清理旧证据。
