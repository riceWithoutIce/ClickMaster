## 范围与已确认参数

- 关联 R03、R04、R05、R07、R09/R10 的单次部分，支持左键、右键、单个键盘按键三选一。
- 点击“单次测试”后固定 3 秒倒计时，界面显示剩余时间，方便用户切到其他工作窗口；结束后一次按下与释放。内部固定约 50 ms 投递间隔，不增加参数设置；实际调度及目标处理时间非精确承诺。
- 键盘下拉为 A–Z、0–9（主键区）、空格、回车、方向键，默认空格；不用全局录入/组合键/文本输入。后端严格白名单，不接收任意消息/句柄或原始 VK 数据执行。
- 鼠标默认当前客户区中心，支持自定义整数 X/Y；按下前读取当前客户区并校验坐标。中心随实际尺寸计算；位置均为客户区像素，不包含边框/标题栏，不做比例定位。除了客户区边界，还须满足鼠标消息有符号 16 位坐标可表示范围，不能静默截断或取模。
- 不要求目标前台，不主动激活/显示/移动目标，不移动真实鼠标。未承诺最小化兼容；按下前目标最小化或客户区不可用应给出明确未发送结果。隐藏窗口若身份/必要坐标可验证，不因不在前台而拒绝；能投递不等于玩法响应。

## 执行与停止约定

1. 调度与计时在 Rust 后端，不依赖前端计时器；请求捕获可信绑定 identity + epoch 和输入配置快照。前端不能自己提供目标 HWND/PID 决定投递。一次只允许一个待执行/执行中的任务；重复点击不得并发或排队多次。
2. 倒计时期间可取消；解绑、重新绑定（包括同目标重绑）、身份失效或退出程序取消未开始的投递，不跟随新实例。切页、主窗口收起不应产生第二次任务或重置计时；倒计时快照不随草稿变化，建议操作期间禁用相关输入项。
3. 按下前及释放前验证原 identity 和当前 binding epoch；绑定转换不能先替换再让旧任务向新目标发送。取消/解绑/换绑遇已投递按下时，仅原绑定仍可验证时完成配对释放，再完成转换；原身份失效不得为释放而向替代窗口投递。
4. 通过 `PostMessageW` 只投递绑定窗口。鼠标 WM_LBUTTONDOWN/UP 或 WM_RBUTTONDOWN/UP，wParam按正确按钮状态，lParam打包已校验的客户区坐标，释放用同一坐标。键盘 WM_KEYDOWN/UP，正确单次repeat/scancode/方向键extended/up位；不触发全局输入或读取/改变键盘设备状态。
5. 每个阶段记录投递结果，至少保留当前/最近任务的脱敏内存摘要与错误码，明确 pending/countdown、sending、已投递、取消、拒绝/失败及部分投递（按下成功而释放失败/身份失效）。不能将部分失败报成完整成功；不自动重试输入，不回退 SendInput/注入。
6. 已入队消息不能撤回；取消仅能阻止尚未开始的新操作或等待，已发送按下仍需按上述语义释放。关闭/退出路径取消倒计时，并有界处理正在配对的约50ms释放，不能留下隐形长按调度线程或影响可恢复退出。
