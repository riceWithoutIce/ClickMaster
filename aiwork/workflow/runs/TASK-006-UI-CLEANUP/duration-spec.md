# rc.1执行持续时间契约

状态：2026-10-22用户已确认功能与参数边界；当前为开发准备，未实现。

## 设置与展示

- 执行参数页直接提供“永久 / 限时”，默认永久；永久不创建时长截止，不以0、空值或特殊巨大数代替模式。
- 限时使用时/分/秒整数输入：小时0～99、分钟和秒0～59，总时长1秒～99时59分59秒（359999秒）。空值、小数、负值、非有限值、越界及总计0均拒绝，不夹边、不进位修正；前后端一致校验。
- 保留间隔设置：默认2000/2000毫秒，消息100～60000、IPC2000～60000，最小不大于最大；完整操作后独立均匀等待，不追赶补发。
- 永久模式不要求隐藏的限时草稿有效；“执行一次”不受重复间隔/持续时间草稿的无效值影响。重复任务开始前验证当前生效模式及参数，运行期间锁定所有执行参数。
- 底部显示当前运行状态、本轮已执行次数和时间。永久显示“永久 · 已运行HH:MM:SS”；限时显示已运行及剩余时间。时间按秒呈现，不为秒级显示降低后台截止检查频率。
- 准备阶段显示3秒准备，执行计时尚未开始；下一次等待与总剩余时长分别表达，不复用一个含义模糊的倒计时。
- 停止后保留本轮耗时、次数和结束原因，耗时冻结、不继续随页面时钟增长。再次开始新一轮，重新准备、计时、计数。
- 参数仅会话内保留，切页/收起不丢草稿；不新增持久化配置。重启为永久、待命、无有效绑定，不自动执行或恢复。

## 起止与停止语义

两通道统一在3秒准备结束、进入实际执行阶段时确定本轮计时起点；第一轮不额外等待间隔。计时覆盖操作耗时与轮间等待，使用单调时钟，避免修改系统日期影响时长；派生deadline及算术需检查溢出。

限时到期进入既有统一停止路径；等待时及时检测，下一次发送前再次校验截止，不能因为等待间隔或单次IPC传输预算更长而越过时长开始新操作。IPC连接/写/读取阻塞期间也需父端监督检测到期并清理直接持有的自有Child，不等到原60秒预算才处理到期。不更改原传输独立超时/身份检查规则，不绕过清理门槛。

已入队消息或已发出IPC帧不能撤回。按下已投递时，仅原身份仍有效才完成配对释放；到期不能阻止必要释放而留下按下状态。实际退出和到期采用原取消/清理流程；清理确认前保持停止中，无法确认仍保持锁定及失败说明，不能显示正常完成。界面中的限时剩余到0不等于所有清理已完成，不承诺精确毫秒停止。

永久模式正常运行直到用户按钮/F8/托盘停止；目标失效、身份变化、执行失败/超时、热键服务异常、实际退出仍终止。收起到托盘继续执行。无新暂停/续跑能力，“手动暂停”沿用停止；无定时启动、次数限制或自动重试。

结束原因直接可见：手动停止、时长已到、目标失效、执行失败等；诊断保留原始阶段和详细原因。失败/部分投递/清理未确认不可被“时长已到”覆盖成成功；明确区分截止触发原因与实际清理结果。时间总结以执行阶段结束为口径，清理进度独立呈现。

## 验证重点

用fake clock/adapter及已有非游戏fixture验证默认永久无时长截止、限时边界、准备阶段不计时、到期早于下次间隔、截止边界不发新轮、按下后到期配对释放、IPC等待/阻塞期间到期及自有Child清理、异常原因保留、结束摘要冻结、重新开始和锁定。不得为99小时边界真实等待，不注册真实F8或自动操作用户桌面/游戏；真实短时体验由用户验证。既有单次、随机区间、身份与停止、槽位有界及配置回归保留。
