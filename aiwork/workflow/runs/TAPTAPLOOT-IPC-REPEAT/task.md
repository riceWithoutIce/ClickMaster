# IPC 单次确认与低频验证

日期：2026-10-22。用户对“先单次确认读取，通过后每2秒最多5次，F8停止，60秒总时限，仍用独立工具”回复“好的 我们继续”。授权此限定开发、独立审核及主协调者分阶段真实验证；保留旧IPC-POC、IPC-DRAIN及修复所有证据，不重用旧attempt或修改产品。

## 阶段与授权

1. `single`：新任务固定runtime/single，原子attempt，只发数量1一次；5秒准备、客户端身份确认、写与drain分别记证、成功后观察约3秒。
2. `repeat`：新任务固定runtime/repeat，另一个原子attempt，必须先核验本任务single完成读取、正常关闭、原目标身份仍有效，并有主协调者落盘的“用户人工确认单次有效”摘要。不能仅凭写成功自动推进。用户无需提供数字基线。未得到这次人工反馈时先停在该门槛；此前一轮“成功了”不冒充新single反馈。
3. repeat同一连接内逐帧数量1，最多5帧，发送开始间隔至少2秒（单调时间），上一帧drain确认后才发下一帧；延迟不补发，不批量数量5。成功完成后观察约3秒；任何阶段失败、取消、超时、目标/窗口失效或进入前台就停止，不重试/重新连接。
4. 本任务只有以上两个固定attempt，不能用自定义证据/运行目录绕过。前置拒绝也消耗对应attempt。真实入口仅主协调者执行，每阶段最多一次。

## 继承与新增运行边界

- 复用已审核coder-r1的UTC/小数生产计时链，沿用10秒drain和2秒写预算，准备5秒、连接最多20秒；每阶段从自有worker启动起总监督上限60秒（编译在此前完成）。超过总限可不足5次，不能为凑次数延长或补发。阈值受OS调度及最多2秒退出等待限制，不承诺硬实时。
- 目标是当前唯一TapTapLoot实例，精确EXE/已知主程序集hash、原创建时间和保留查询句柄，唯一UnityWndClass可见、非最小化、后台、客户区有效；每帧唯一写前重验同一客户端与原进程窗口。repeat不能自动跟随游戏重启，single→repeat需核实原目标连续身份。脱敏持久化身份可用创建时间等字段的hash，不落真实PID/HWND/路径。
- 管道仍固定TypingFarmer，first-instance/max1/current-user ACL/reject-remote。已有服务器/身份不符则停止，不接其他通道。不改游戏、不读其进程内存、不附加调试器、不发任何键鼠/PostMessage、不抢焦点、不移动鼠标，不下载新依赖。
- F8通过RegisterHotKey（无键盘hook）注册测试急停；冲突/注册失败则不创建worker、不发数据。热键注册及注销在同一有界生命周期中，所有结束路径释放。测试结束不继续占用F8。纯自检不注册真实热键。真实F8送达/取消证据单列，不以策略测试冒充实际热键验收。
- launcher监听停止；确认处理取消后不再安排新帧，仅终止本次直接创建且持有的worker对象（不杀树/不扫名称/PID），有界等待退出并记录。可协作取消，但drain同步阻塞必须可通过自有worker结束解除。取消时可能已有在途帧，不撤回、不假称未发送；持久回执保守保留每帧write-attempted/completed/drain状态，未确切终态记未知。
- 每帧写前持久化阶段，原子替换worker回执，父读取共享Delete；监督使用实际修复后的共用生产函数，不复发UTC隐式Parse或Math.Max整数精度问题。正常Dispose与OS回收/退出未确认分开。
- 主协调者发送前提示用户暂停键鼠、留意游戏且保持游戏非前台，不要求发送数字。用户观测与精确计数/完整隔离分别记证。F8本身是真实按键，人工取消与精确计数验收分开。

## 角色与验证

Coder唯一写新诊断源码 `build/verification/TAPTAPLOOT-IPC-REPEAT/coder/`，交接放本目录。默认入口仅编译/纯文件与时间/策略测试，禁止默认连接游戏、注册F8或启动worker。所有进程TEMP/TMP/TMPDIR和测试编译产物仓库内；文档/回执脱敏，无本机路径、真实PID/HWND、原始异常或票据。

核心测试覆盖：固定帧与上限、上一帧未drain不发送、最小2秒且不追赶、取消/目标无效不再安排、10/60秒边界、single门槛及缺人工反馈拒绝repeat、原子阶段与发送不确定性、历史UTC/小数回归、固定attempt。假fixture必须走共用生产逻辑，禁止镜像断言凑数。不能为了自检启动真实worker/管道/游戏或发送热键。

Coder提供稳定源码hash和自检交接后，独立Verifier只读审核冻结契约、主要路径、单实例/停止/发布边界和声明证据，用独立输出；findings一次性返回用户裁定，不直接要求Coder修复。主协调者核对后进入已授权single，repeat等本次single的人工结果，不自动越过门槛。
