# 0.1.0 发布前人工回归

状态：用户已回复“验收通过”，按本清单范围记人工总体通过；详见 `human-acceptance.md`。以下保留交付时步骤，不表示自动操作电脑或发送游戏输入。

测试包：`build/staging/TASK-015-RELEASE-PREP/ClickMaster-0.1.0-windows-x64.zip`，指纹见同目录 `source.json` 和 `SHA256SUMS.txt`。

请先自行退出旧 ClickMaster 副本，避免 F8 和专用管道被占用；不要删除旧 data。将 ZIP 解压到本项目内独立目录，例如 `build/verification/TASK-015-RELEASE-PREP/human/`，运行其中 EXE，勿直接在 ZIP 内运行。

1. 确认界面/诊断版本为 `0.1.0`，图标、三个设置页、窗口详情、更多→诊断显示正常；按 EXE/标题/PID 筛选并绑定目标，必要时显示后台窗口。
2. 在已核验 TapTapLoot 目标选择专用 IPC，测试单次，再以默认 2000 毫秒固定间隔短时运行；确认实际游戏响应、当前工作窗口无多余输入，鼠标不移动且目标不抢焦点。随机区间可用 2000～2500 毫秒短时检查；不必复测 1 毫秒压力。
3. 分别用按钮、F8 和托盘停止；用 5 秒限时确认准备结束后开始计时、到期结束；永久模式确认可手动停止。次数是传输统计，停止后游戏处理已有缓冲不等于新发。
4. 验证最小化到托盘、恢复、可选任务栏保留，以及关闭时收起/退出/取消。准备或运行中关闭目标后，工具应停止且不得自动跟随重启；如出现异常，停止并反馈，不盲目重试。
5. 退出后确认数据仅在该 EXE 同级 `data/` 生成。重新启动应待命、不自动执行或恢复绑定；确认最小化偏好保留。已有运行数据不随包分发，不要在运行中删除缓存。

消息模式如需复查，可用已知可响应的计算器内容窗口测试数字键；不能用 TapTapLoot 消息无效当作正式版新增回归。未测的目标/输入写未测，不扩大已有兼容性记录。

可直接反馈“启动/界面、IPC、固定/随机、限时、按钮/F8/托盘、关闭目标、数据/重启”各项通过或异常；附异常文字和版本即可，不需要人工抄录资源或游戏计数。Windows 11、缺失 Runtime、长时间和真实性能仍独立标未测。
