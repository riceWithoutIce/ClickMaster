# 重复与停止人工验收

状态：用户对本轮交付步骤回复“验收通过”，固定/随机IPC重复及按钮/F8/托盘停止记人工PASS；其余专项未单独反馈，详见[验收回执](acceptance.md)。入口为`build/verification/TASK-005-REPEAT/coder/final/ClickMaster.exe`。下文保留原测试清单供追溯，不要求用户重复执行已通过流程。主协调者/Coder/Verifier未自动打开普通UI、查询游戏、创建游戏管道或发送，不代替用户键鼠操作。

## 主要流程

1. 自行关闭旧ClickMaster/独立IPC测试器，打开本轮最终验收入口。默认待命，不自动执行。绑定目标，选择通道与输入方式。
2. 执行参数页先用2000/2000毫秒固定间隔。开始后3秒准备，切换到其他工作窗口、目标保持后台且非最小化。准备结束才第一次；每轮完成后再等待设定时长，实际节奏包含消息释放或IPC读取耗时。
3. 观察游戏持续响应和已完成次数；次数是投递/传输完成次数，不是游戏统计。工具按钮及用户操作键鼠也可能让游戏计数，请区分。
4. 点击停止，或另一轮按F8，或收起后用托盘停止，分别确认不再开始新操作、显示终态、控件解锁。已发送消息/在途帧无法撤回，不能据停止后处理的旧帧判定又发了新帧。
5. 停止后改为2000/4000毫秒，再开始验证间隔变化；首轮仍只3秒准备，不额外等待随机区间。运行期间不可改参数、通道或绑定。最小大于最大、非法数值及跨通道低于下限应提示且禁止重复开始，不静默改值；单次仍独立可用。
6. 收起到托盘应继续运行，托盘显示实际状态并能停止；实际退出则先停止和清理。不要求为验收自动重启游戏；若手动关闭目标，任务应停止且游戏重启需重新绑定。
7. 有条件时分别验证消息通道计算器数字键和IPC游戏重复；原单次仍应可用。未操作的通道或场景保留待验，不以另一通道替代。

## 需要分别反馈

固定/随机持续响应、界面停止、F8停止、托盘继续/停止、退出及目标失效、工作窗口没有额外输入/鼠标未移动/游戏未抢焦点。F8冲突可在实际已有占用环境观察：应禁止开始并提示，不能在没有有效停止热键时开始；不为测试擅自改变外部程序热键。

出现干扰或退出后继续触发，立即停止并反馈，保留data，不自动追加次数/换技术。生产数据仍跟随实际EXE，不能写用户目录；历史数据不自动清理。清单本身不是逐项通过证据，人工结果以验收回执为准。
