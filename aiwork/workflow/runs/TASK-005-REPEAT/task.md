# TASK-005-REPEAT：随机区间重复执行与统一停止

日期：2026-10-22。用户确认两通道重复执行/F8/托盘规则后，要求最小与最大间隔随机区间，并回复“同意，我们继续”。本轮授权范围内开发、自测、构建本地测试包及稳定快照后独立审核；真实桌面/游戏验收由用户操作，不自动查询游戏、启动普通UI或发送。

## 冻结行为

- 保留现有窗口消息和TapTapLoot专用IPC单次，新增“开始”持续重复直到停止；不沿用测试器最多5次限制。单次与重复互斥，默认启动/重启不执行，默认窗口消息、不自动重绑或切换通道。
- 执行参数页两个整数毫秒输入：最小/最大间隔，默认均2000；相等为固定间隔，无额外随机开关。窗口消息100～60000，IPC2000～60000，最小不得超过最大；前后端拒绝空值、非整数、非法范围和溢出，不夹边/静默修正。切换通道不自动改写区间；当前值不适用则说明并禁止开始。本轮参数会话内保存，不新增配置持久化和旧配置迁移。
- 开始后3秒准备，随后第一次；每次完整操作结束后，在闭区间[min,max]内独立均匀抽取整数等待，等待结束后才开始下一次。固定值不依赖随机源。无赶点补发、无重叠/堆积。首帧不额外等待随机间隔；单次不受重复参数无效影响。
- 完整操作：消息为按下和释放都成功投递（保留约50ms配对间隔）；IPC为数量1写入并读取确认。两者均不证明游戏已响应。IPC不得用数量N替代N次，连接/写/读取超时仍需有界；60秒应是单次传输预算，不能让持续任务每60秒自动结束。
- 每轮及等待时核验原绑定实例/路由或IPC客户端资格。窗口/进程失效、身份变化、消息失败/部分投递、IPC失败/超时立即停止，不重连重试、不自动切通道或跟随重启。后台非最小化、原身份/版本/ACL/first-instance/本地客户端等已有IPC边界保留。
- 前后端锁定执行期间目标/通道/输入/参数，停止结束且清理确认后解锁；单次/重复统一停止按钮。已发出的消息/IPC帧不能撤回；消息按下后只在原身份仍有效时配对释放，不向替代窗口发。清理无法确认保持锁定并说明，不冒称成功。
- 全局F8固定首版，不做自定义录入。倒计时及执行期间有效，包括单次和重复；必须先可靠注册并收到成功，再允许开始。冲突/注册或服务失败禁止开始，注册不吞掉用户其他输入，不使用键鼠hook。结束/停止/异常/退出释放。F8只负责停止，不启动或切换。
- 收起到托盘继续运行；托盘菜单启用“停止”，提示待命/单次/重复/停止中等实际状态，不仅静态文字。托盘停止、主界面停止、F8及实际退出都走同一取消语义。实际退出先停止并清理自有worker，收起不等于退出。
- 状态至少区分3秒准备、完整操作中、下次等待、停止中/终态；显示已完成次数（传输/投递次数，非游戏计数）和下一次等待信息，不把等待写为游戏成功。计数和时钟不能溢出后额外发送。

## 实现和存储边界

延续Tauri/Rust/Vue及现有Windows API，不新增依赖下载/全局安装或.NET分发。Windows RegisterHotKey采用拥有消息循环的线程或已验证主线程处理；注册/注销在可靠线程执行。随机可复用现有BCryptGenRandom，采用拒绝采样等无偏方法，不新增随机库。调度使用单调时钟和完成后等待，实际时间受系统调度/处理耗时影响。

IPC保留同EXE受控worker及直接Child所有权，只终止自有进程、不按名称/PID/树终止。可复用每次传输已有worker模式或在受控会话内循环，但必须独立保留原实例、逐帧确认、停止与超时。不得随每帧无限新增目录/日志；复用有界状态/临时槽位，只能清理本轮直接创建且worker已退出的临时资源，不清理旧任务证据或用户既有数据。会话历史保存需有明确上限且不能每帧无限积累；必要取舍报告交接，不擅自停止用户持续任务来冒充日志控制。

构建/缓存/temp/fixture输出在项目内，按generated-data.md；运行数据实际EXE同级data，无用户目录/CWD回退。生产及fixture不持久化原始PID/HWND、私人窗口标题、路径、授权秘密；数据脱敏。无SendInput、焦点/鼠标移动、注入、驱动、游戏修改。
