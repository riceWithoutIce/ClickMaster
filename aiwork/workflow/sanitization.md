# 文件与文档脱敏

## 适用范围

项目内持久保存和对外交付的文件均适用，包括源码与注释、配置、脚本、文档、AI 交接记录、命令示例、日志摘录、截图、发布清单及打包内容。新增或更新文件时同步脱敏，不等到发布前才处理。

## 路径与敏感内容

- 不写入本机绝对路径、用户目录、用户名、机器名、个人共享路径或其他可识别本机的信息。
- 项目路径使用仓库相对路径；需要表达根目录或外部位置时使用 `<repository-root>`、`<target-exe>`、`<output-dir>` 等占位符，并说明含义。
- 命令注明相对执行目录；脚本在运行时解析项目根目录或从参数取得外部路径，不硬编码开发机器位置。执行工具所需的临时绝对路径不直接复制进持久记录。
- 不保存密码、令牌、API 密钥、私钥、认证头、Cookie、带凭据的 URL、连接凭据或其他敏感内容。示例统一使用 `<redacted>` 或明确的虚构值；不保留真实凭据片段。
- 目标 EXE、PID、窗口信息仅保留复现所需最小内容；窗口标题、命令行或截图涉及个人内容时使用别名、摘要或遮盖，并注明已脱敏。
- 合法公开的技术资料链接可以保留；内部服务地址、账号、个人信息及未授权公开的业务数据应移除或替换。

## 日志与证据

- 工具输出、报错堆栈、环境变量和截图先检查再保存或分享。只摘取必要内容，不直接粘贴完整环境、命令历史或配置。
- 截图应裁剪到必要区域并遮盖敏感内容，导出后再次检查可见文字与文件元数据；不同时保留未脱敏原图或可恢复敏感内容的图层。
- 占位符在同一记录中保持一致，保留错误码、调用顺序等必要诊断信息；注明哪些字段被替换，避免将脱敏示例误当作原始证据。
- `.gitignore` 不代替脱敏；忽略文件和本地日志也不得成为原始敏感内容的归档位置。后续构建应采用路径重映射等可用配置，交付前检查包内内容与路径元数据。

## 执行与检查

- Coder 交接前检查本次修改及附带证据；主协调者整理文档时遵循同一规则。
- Verifier 将脱敏作为约定检查项，检查稳定快照和待交付内容；报告只包含脱敏后的描述，不把泄露内容复制进 finding。
- 检查包含本机路径、用户标识、凭据和截图可见内容；文本扫描只能辅助发现问题，不能视为所有敏感信息均已排除的证明。
- 发现问题先停止传播相关内容，在授权范围内替换或移除；若真实凭据已泄露，告知用户处理撤销或轮换，不能用删除文本代替凭据处置。

本约定不授权批量清理历史、改写 Git 历史或删除未知文件；发现历史残留时先记录其位置与影响，描述本身也须脱敏。
