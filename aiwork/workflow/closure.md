# 验收记录、交付与收尾

## 结果状态

| 状态 | 含义 |
| --- | --- |
| PASS / 通过 | 对指定快照按约定方法执行，证据支持该验收条件 |
| FAIL / 失败 | 已执行，观察到不符合验收条件的结果 |
| NOT RUN / 未执行 | 没有运行对应检查或实际观察 |
| INSUFFICIENT EVIDENCE / 证据不足 | 已有材料不足以支持判断，注明缺少什么 |

独立记录各项状态，避免一个总 PASS 掩盖未执行的目标兼容性或交付门槛。证据按 [验证方案](../validation.md) 分层：源码、构建、可控窗口、API/日志、目标实际观察；安装包与分发验证另列。

## 目标游戏与人工验收

- 源码或构建通过不代表后台游戏响应；PostMessage 返回成功不代表玩法已触发。
- 实际目标验证单独安排，默认由用户按验证方案观察；自动启动游戏或代替人工操作需在任务内另行授权。
- 记录目标进程实例、窗口、工具快照、输入方式、间隔、环境和实际结果，不将一个目标或一种输入的结果推广到其他情况。
- 单次输入均无效或干扰工作窗口时，按验证方案停止，保留证据并返回讨论；不升级输入技术。
- 未完成目标实测时，可以记录开发或源码验收已完成，兼容性仍为未执行或证据不足。

## 交付与归档

开发验收、目标实测和版本交付是不同门槛。只有相应授权明确后，才执行提交、打包晋级、发布或清理等操作；已经给出的对应授权不重复申请。

交付前将待交付产物与来源快照、版本、哈希、检查结果和已知限制关联，按 [脱敏约定](sanitization.md) 检查文件内容与路径元数据。归档、晋级、数量上限及失败恢复分别遵循 [release](../../release/README.md)、[build](../../build/README.md)、[version](../../version/README.md)；不在 workflow 中另设一套保留规则。

清理限定于明确受管理的本项目输出。先核对清单与保留计划，保护未解决问题及唯一验收证据；未知历史残留先盘点，文件被占用时停止受影响操作，不结束外部进程。

## 本轮收尾

主协调者完成以下记录，再向用户返回简短汇总：

- 完成范围与稳定快照。
- Coder 自测及 Verifier 实际结论；未安排独立验收时明确说明。
- 尚未执行或证据不足的检查，尤其是目标实测与发布门槛。
- Findings 的用户处置、延期项、已接受风险和交付限制。
- 下一步及所需用户决定；已达到停止条件的审核不继续扩张。

更新 [开发日志](../devlog.md)；仅在对应条件有证据时更新 [roadmap](../roadmap.md) 状态。关键证据存入任务记录、[debug](../debug/README.md) 或发布元数据，不能只留在会被轮换的普通日志中。
