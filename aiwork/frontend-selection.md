# 前端与包管理器选型

日期：2026-10-21。

状态：用户已确认采用 **Tauri 2 + Rust + Vue 3 + TypeScript + Vite + npm**。决定为通过集成规划；依赖安装、工程初始化、实际构建和后台输入验证尚未开始。

## 目标与基线

本工具以窗口列表、输入配置和运行状态为主要界面，需支持圆角与基础动效，并控制依赖和维护成本。当前基线为目录与文档，没有可运行界面或既有前端框架需要兼容。

Tauri 官方推荐 Vite 用于 Vue、React、Svelte 及原生 TS 等本地前端；无需为当前功能引入 SSR 服务。框架选择不改变 Rust 后台输入与停止职责，也不能提升游戏对窗口消息的兼容性。

## 候选比较

以下是维护取舍判断，不是包体、内存或性能实测。

| 候选 | 能力与成熟度 | 集成与生成物 | 主要取舍 | 决定 |
| --- | --- | --- | --- | --- |
| Vue 3 + TS + Vite | 成熟的组件、响应式状态、表单和局部样式 | 本地静态构建，接入 Tauri | 符合配置表单与状态界面需要，仍需维护框架依赖 | 用户已确认 |
| React + TS + Vite | 成熟组件生态，可覆盖相同界面 | 同一静态构建边界 | 当前没有必须使用其生态的需求 | 不采用，保留比较 |
| Svelte + TS + Vite | 可覆盖组件、状态与动效 | 同一静态构建边界 | 可行，但本轮未选择其组件体系 | 不采用，保留比较 |
| 原生 TS + Vite | 无额外组件框架 | 同一静态构建边界 | 需自行维护更多 DOM 与状态同步 | 不采用，保留比较 |
| 维持目录与文档 | 无新增依赖 | 不产生前端构建数据 | 无法验证界面或交付应用 | 仅作比较基线 |

前三种方案均有公开维护与 Tauri 接入路径；具体依赖版本及兼容组合仍需初始化任务核对。它们共用项目依赖、构建输出与忽略边界，不因换框架改变运行数据约束。

## 已确认组合

- Vue 3 组织界面，TypeScript 描述前端数据与通信类型，Vite 负责开发与静态构建。
- npm 管理前端依赖，提交 `package-lock.json`；首轮生成锁文件后，验收使用 `npm ci` 还原，禁止将其当作新增依赖命令。
- npm 已在上一轮只读核对为可用，无需额外安装包管理器。pnpm、Yarn 属于可行备选，本项目暂无多包仓库等需求支撑切换。
- 基础圆角、悬停和过渡使用 CSS；先实现少量项目控件，组件库、动画库、路由与全局状态库按实际需求另行评估。
- 输入循环与停止由 Rust 管理，停止动作不等待前端动画完成。
