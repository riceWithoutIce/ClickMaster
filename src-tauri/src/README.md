# Rust 源码

`main.rs` 是桌面入口；`lib.rs` 管理窗口、托盘、关闭二级选择、便携数据、版本/绑定/单次输入IPC及生命周期；`settings.rs` 负责偏好与原子保存。`targets.rs` 持有后端候选身份/绑定状态并通过可注入查询测试失效；`windows_query.rs` 为只读Windows查询适配层；`window_policy.rs` 处理自身窗口收起及失败恢复。单次输入已接入，重复执行及全局热键未开发。

候选规则：默认EnumWindows顶层可见、有标题，包含最小化窗口；普通范围排除工具型窗口；开启隐藏/后台范围后允许隐藏、cloaked、无标题及工具型应用顶层窗口。始终排除自身PID、桌面/系统shell句柄及已知桌面/任务栏类、noactivate窗口，以及没有appwindow样式的owned辅助窗口。只枚举窗口，不枚举无窗口进程。IsWindowVisible、IsIconic和Dwm cloaked状态用于区分可见/最小化/隐藏。独立主窗口以HWND分别保留，不按EXE/PID合并；必要身份读取失败项只返回排除数量。完整进程路径只在内存解析文件名，不写日志。

候选展示筛选与live identity校验分开：inspect不以可见性、标题或辅助样式变化判失效。刷新使旧候选token过期，仍保留可验证的绑定，即使新列表不含目标；隐藏、空标题及范围切换不解除绑定。实际销毁、退出、必要权限丢失及可信身份变化仍解除，不自动跟随重启。状态变化会更新绑定摘要和revision。

可信身份包含HWND、PID、进程创建FILETIME和窗口线程ID，绑定前重新查询，比对后才绑定；周期检测在Rust后台线程运行，不依赖页面和WebView计时器。只通过Get/Enum/Query API读取目标，不移动、激活或发送消息。Windows没有在本查询方案中提供可跨HWND快速复用验证的窗口创建序号；同进程同线程极短时间销毁并复用完全相同HWND的竞态不作额外保证。单次输入发送前独立重新验证，窗口查询模块本身不发送输入。

上段只读边界适用于窗口查询模块；单次输入模块按下/释放前复验同一可信身份与epoch后可PostMessage。`input.rs`为纯消息构造/状态机，`input_native.rs`为唯一投递适配，`input_runtime.rs`为10ms节拍后端worker。请求捕获绑定和参数快照，固定3秒倒计时、正常约50ms配对释放；一次只容许一个任务，不排队或重试。左右键携带正确按钮状态及校验后的有符号16位客户区坐标；键盘严格A–Z/0–9/空格/回车/方向键白名单，用目标线程布局映射扫描码、extended及释放位。没有CHAR/组合键、全局设备状态或SendInput回退。

全部任务入口/worker按input→targets锁序；同一锁域内完成阶段身份检查和PostMessage，绑定切换先取消/配对释放再更改epoch。取消/退出可缩短剩余配对等待，原身份仍有效才释放；无效则报告部分投递，禁止向替代窗口补发。解绑/换绑也先配对，再在不持targets锁时收起预览，避免其命令确认和目标锁互等；仍持input锁防止中途新增任务。退出先阻止新任务、取消/配对，再停止并join输入worker。内存保留最近任务/每阶段投递与错误码，不将入队成功等同目标响应。

按下前拒绝最小化及无有效客户区；隐藏且身份/坐标可验证不因前后台拒绝。客户区在临时PMv2线程上下文读取，恢复原上下文，不依赖overlay。Coder/Verifier只使用fake adapter；获准的真实计算器主程序验证由协调者独立执行并记录，编译/纯测试不替代目标实际响应或输入隔离证据。

`routing.rs`在既有targets锁域中持有独立接收候选token、接收身份/epoch和选择状态，`routing_native.rs`只读发现ApplicationFrameWindow内可见非cloaked的CoreWindow。普通窗口接收自身；唯一内容自动选，多候选待明确选择，可显式选择自身。宿主查询失败不回退；失效后清空接收候选并要求重新绑定。周期/阶段校验仅检查原父子身份，不重新发现或追踪替代窗口；候选列表刷新不改变有效路由。绑定/接收者切换先取消并向仍有效原路径配对释放。

输入快照同时捕获绑定身份/epoch及接收身份/epoch，阶段按input→targets锁序复验两者与归属关系。PostMessage只发接收窗口，键盘布局来自接收线程；结果保留该次接收摘要，不随以后选择变化。鼠标先校验绑定客户区位置，再在同一个PMv2上下文经ClientToScreen/ScreenToClient转换到接收客户区，校验最终非负/尺寸/有符号16位；失败不夹坐标、不回退。预览仍针对绑定客户区，不改绘制路径。HWND同进程同线程快速复用的原有限制仍保留。

后台发送只采用已冻结的消息路线，不自动回退全局输入，不移动真实鼠标或主动激活目标。具体行为以 [冻结需求](../../aiwork/requirements.md) 为准。

## 原生坐标预览 POC

`overlay.rs`只包含纯几何/状态策略和fake renderer测试；`overlay_native.rs`管理Win32/GDI资源；`overlay_runtime.rs`是专用线程的命令/确认与消息循环。默认关闭、仅会话内；没有新增WebView、数据文件或第三方依赖，windows-sys仅补GDI/HiDpi/LibraryLoader feature。

启用时每约80ms验证后端绑定身份，仅读取当前目标的可见性、最小化、cloaked、客户区及必要前台句柄。仅匹配的前台目标显示；切其他软件/隐藏/最小化暂停，返回后恢复。绑定代次只随绑定/解绑/失效改变，不随标题/候选刷新改变；IPC携带预期代次拒绝旧草稿意外跟随新绑定。解绑/换绑先通过命令确认关闭，周期失效也关闭；退出发送shutdown并join线程。

原生窗口为WS_POPUP，使用LAYERED/TRANSPARENT/NOACTIVATE/TOOLWINDOW及色键透明；命中测试返回HTTRANSPARENT，鼠标激活返回MA_NOACTIVATE，SetWindowPos始终NOACTIVATE。只在目标前台使用客户区大小的临时topmost显示，没有覆盖全桌面的窗口。覆盖层归自身PID，因此两种候选范围均排除。窗口/GDI对象在专用线程创建/销毁；选入DC的笔/字体恢复旧对象后释放，stock brush不删除；创建、绘制、更新或隐藏失败关闭预览并报告，可重试。

专用线程进入PMv2 DPI上下文，GetClientRect的两个角经ClientToScreen映射为物理屏幕像素；负屏幕原点保留，位置不二次乘DPI。中心随当前客户区宽高取整；自定义为当前客户区非负整数像素，不按比例缩放；越界/小数/空值保留边框但不画点击点。仅装饰文字/十字大小按覆盖窗DPI调整。线程退出恢复先前DPI上下文。实际混合DPI、鼠标穿透、焦点、视觉和独占全屏行为没有自动化/实机证据，留给本轮人工POC验收；不宣称正式集成或输入兼容性通过。
