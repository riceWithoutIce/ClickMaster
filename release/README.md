# 发布产物

本目录只保存经过验证并显式晋级的交付产物，不放编译缓存、依赖、源码拷贝或每次开发构建。除目录说明外，发布槽位内容默认不纳入 Git。

## 数量上限

| 位置 | 内容 | 上限 |
| --- | --- | --- |
| `current/` | 当前正式版的一套产物，版本由清单标识 | 1 个版本 |
| `archive/<version>/` | 最近两个历史正式版，含上一版回退包 | 2 个版本 |
| `preview/<version>/` | 当前候选版的一套产物 | 1 个版本 |

合计最多 **4 套版本产物**。保留数为本轮建立的默认规则，后续用户可以明确修改。不能用无限增加的 archive、backup、old 或日期文件夹绕过上限。

每套默认只保留最终选定的一种架构、一种主要分发格式，加小型清单/校验文件；架构和格式本身尚未确定。若以后需要多架构或多格式，应先调整产物预算，不默认扩展一套的含义。

候选版成为正式版时迁移同一份已验证产物，不继续在 preview 重复保留。归档是移动并校验，不再给每个版本额外制作一份 ZIP 备份。

## 晋级顺序

1. 在 `build/staging/` 准备本次产物，核对版本号、SHA-256、来源快照和验收记录。
2. 确认版本槽位调整计划及待淘汰产物，校验清单只包含受本项目管理的文件。
3. 将原 current 作为整体移动到其版本归档目录，再将已验证产物放入 current；任一步失败保留可恢复状态，不能先删除唯一可回退版本。
4. 更新 `version/releases.json` 的状态和路径；成功后按上限淘汰最旧历史正式版，候选版槽位保留最新候选。
5. 校验路径、哈希、索引与数量一致。操作失败则停止继续晋级/淘汰，不重命名不完整产物为成功发布。

晋级期间允许短暂出现额外一套以支持恢复；不得在超过上限且未解决时继续下一轮发布。临时保留不能变成无限历史归档。

## 清理边界

- 仅清理清单能归属且哈希匹配的过期产物；出现未知文件、哈希不一致、文件占用或未关闭的问题证据时停止并报告。
- 发布索引、变更说明和必要验证证据不跟随二进制淘汰。
- 需要固定某个问题版本时占用现有历史/候选槽位，不能无限新增“永久保留”例外；与当前/上一版回退保留冲突时暂停晋级，先调整保留决策。
- 不涉及用户数据、WebView 缓存、其他项目或外部进程，不因发布清理而结束进程。
- 本轮仅建立规则；没有发布包，也没有执行归档、删除或自动清理。后续脚本需先提供可审阅的保留/淘汰计划，再执行对应受管理产物的操作。

对外上传、自动更新服务与远程发布不属于该本地目录约定。
