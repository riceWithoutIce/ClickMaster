# 发布产物

本目录只保存经过验证并显式晋级的交付产物，不放编译缓存、依赖、源码拷贝或每次开发构建。除目录说明外，发布槽位内容默认不纳入 Git。

## 保留规则（2026-10-23 修订）

用户已确认：**历史版本留记录，二进制只保留最新已验收版本**。本规则替代此前“当前 1 + 历史 2 + 候选 1，共 4 套”的约定。历史文档与交接记录保留原样，但不再作为永久保留历史产物的理由。

| 位置 | 内容 | 上限 |
| --- | --- | --- |
| `current/` | 最新已验收正式版，版本由清单标识 | 有正式版时保留 1 套 |
| `archive/` | 历史版本记录入口，记录详见版本索引和任务文档 | 不保留历史二进制 |
| `preview/<version>/` 或 `build/staging/` | 尚未正式发布的最新已验收候选 | 首版前保留 1 套，不跨目录重复存包 |

稳定状态只保留最新已验收的一套产物。下一版构建和验证期间可暂存待验包及上一个已验收包；新包验收和替换完成后，记录旧版并淘汰，不转存为无限增长的 archive、backup、old 或日期备份。

每套默认只保留最终选定的一种架构、一种主要分发格式，加小型清单/校验文件；首版已确认 x64 免安装便携发布，建议以一个 ZIP 交付，详见 [运行环境与分发](../aiwork/runtime-distribution.md)。ZIP 是主要交付物，不再额外保存一份完整解压副本。若以后需要多架构或多格式，应先调整产物预算。

用户解压后直接运行 EXE，运行数据写入 EXE 同级 `data/`，详见 [本地数据](../aiwork/local-data.md)。发布包不得带入配置、日志、缓存或 WebView 用户数据；验证在隔离副本进行，不在 release 槽位启动程序。免安装不等于无 WebView2 依赖，也不提前承诺仅单个 EXE 即包含所有必要文件。

归档指保存版本、来源、日期、大小、SHA-256、验收结果和淘汰记录，不保存旧 EXE、ZIP 或完整解压副本。候选晋级不得只改文件名冒充正式版本；正式包准备与验收完成后，淘汰旧候选并消除 preview/staging/current 中的重复包。

## 晋级顺序

1. 在 `build/staging/` 准备本次产物，核对版本号、SHA-256、来源快照和验收记录。
2. 确认版本槽位调整计划及待淘汰产物，校验清单只包含受本项目管理的文件。
3. 准备已验证的新包并核验来源和版本，替换 current；替换完成前暂留旧包，失败时保留可恢复状态。
4. 更新 `version/releases.json` 的状态和路径；记录旧版后淘汰旧二进制及候选重复副本，不再保留两个历史正式包。
5. 校验路径、哈希、索引与数量一致。操作失败则停止继续晋级/淘汰，不重命名不完整产物为成功发布。

晋级期间允许短暂出现额外一套以支持恢复；不得在超过上限且未解决时继续下一轮发布。临时保留不能变成无限历史归档。

## 清理边界

- 仅清理清单能归属且哈希匹配的过期产物；出现未知文件、哈希不一致、文件占用或未关闭的问题证据时停止并报告。
- 发布索引、变更说明和必要验证证据不跟随二进制淘汰。
- 未解决问题优先保留关键报告、失败日志、必要脚本和小型复现材料，不因此永久保留整套历史目录。确实依赖旧包才能复现时，在清理清单中说明具体对象和原因。
- 旧验收副本中的运行数据先提取必要配置和问题日志，再清理无用 WebView 缓存与测试数据；不删除仍在使用的数据、其他项目内容或结束外部进程。
- 当前最新已验收候选为 rc.9，正式版完成验收前保留；正式版验收和替换完成后 rc.9 也可淘汰。本次仅更新规则，未执行归档、删除或发布；执行清理时按具体清单操作。

对外上传、自动更新服务与远程发布不属于该本地目录约定。
